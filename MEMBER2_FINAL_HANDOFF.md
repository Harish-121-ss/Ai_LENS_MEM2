# Member 2: Reliability Intelligence Final Handoff

## A. Member 2 Responsibility
Member 2 owns the local, deterministic Reliability Intelligence pipeline. This includes the normalization of raw agent telemetry into structured runs, the deterministic detection of failure states (timeout loops, wrong tool usage, token anomalies), the consolidation of evidence into structured Incident models, and the generation of Root Cause Analysis (RCA) prompts for LLM modeling (currently mocked).

## B. Completed Stages
- **Stage 2B:** Contracts and Fixtures established for `Run`, `DetectorResult`, `Incident`, and `RCAOutput`.
- **Stage 3:** Normalization logic to transform raw JSON execution telemetry into strongly typed `Run` models.
- **Stage 4:** Deterministic detection strategies created (`timeout_retry`, `tool_loop`, `wrong_tool`, `token_anomaly`).
- **Stage 5:** Incident Engine introduced to consolidate detector results securely, along with RCA Prompt generation and evidence grounding logic.
- **Stage 6:** Local pipeline integration built via an orchestrator that securely links all stages without external dependencies.
- **Stage 7:** Final repository audit, hygiene check, dependency validation, and Member 4 handoff preparation.

## D. Public Entry Point
- **Module:** `agentlens.engine.orchestrator`
- **Function:** `run_reliability_pipeline`

## E. Input Contract
`run_reliability_pipeline(raw_execution: Dict[str, Any], rca_provider: RCAProvider, baseline_tokens: float = 1000.0) -> PipelineResult`
- `raw_execution`: A dictionary representing the raw execution payload.
- `rca_provider`: An implementation of the `RCAProvider` interface (use `MockBedrockProvider` for local testing).
- `baseline_tokens`: Optional token threshold for anomaly detection.

## F. Output Contract
The function returns a `PipelineResult` object containing:
- `run`: The normalized `Run` object.
- `incidents`: A `List[Incident]` of identified failures.
- `rca_outputs`: A `Dict[str, RCAOutput]` mapping incident IDs to their grounded Root Cause Analyses.

## G. Reliability Flow
1. **Normalize:** Raw execution data is normalized into a standard `Run` object.
2. **Detect:** Deterministic detectors scan the run for anomalies.
3. **Incident:** Detected failures are consolidated into `Incident` objects, merging duplicate evidence.
4. **RCA:** A root-cause prompt is generated for each incident and evaluated via the provided `RCAProvider`, then validated for strict evidence grounding.

## H. Evidence Traceability
Every evidence item generated by a detector inherits the `source_run_id` and exact `event_sequence`. This information is preserved when mapping into the `Incident` object and is enforced strictly during RCA grounding validation. If an RCA output attempts to return evidence that cannot be matched to the original Incident evidence via exact fingerprinting, validation fails immediately.

## I. Failure Behavior
- If normalization fails due to invalid telemetry, a `ValueError` or `ValidationError` is raised.
- If RCA generation yields an ungrounded or fabricated evidence structure, validation raises a `ValueError`.
- Exceptions during detector runs or incident mapping directly bubble up to halt the pipeline.

## J. Healthy Behavior
In the event of a normal, healthy agent execution, the `run_reliability_pipeline` returns a `PipelineResult` where `incidents` is an empty list (`[]`) and `rca_outputs` is an empty dictionary (`{}`). No false positive incidents are generated.

## K. RCA Behavior
The RCA generation currently relies entirely on the provided `RCAProvider` abstraction. For local offline execution, `MockBedrockProvider` is used. Production AWS Bedrock integration is left to Member 4. The RCA validation strictly limits the model to reasoning only from provided evidence.
